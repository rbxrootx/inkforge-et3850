# ET-3850 network control and URL inventory

This inventory is based on the extracted XB22Q5 ARM application, the Windows updater bundled with Epson's recovery package, and read-only requests to a local ET-3850 running `05.15.XB22Q5`. A string in a binary is a lead, not proof that the live printer serves that URL.

| Surface | Offline evidence | Live result | Installation relevance |
| --- | --- | --- | --- |
| Web Config administrator | Authenticated menu under `/PRESENTATION/ADVANCED/` includes `NW_WIFI/TOP`, `NW_BASIC/TOP`, `SYS_ENASAVE/TOP`, and `NW_SERVICE_PRTCL/TOP`. | Login with the unchanged default administrator credential succeeded. Forms and scripts were read without storing field values. | `NW_WIFI` exposes enable/disable; `SYS_ENASAVE` exposes sleep and automatic-off timers. Neither page exposed a Wi-Fi driver power-management control or file upload. |
| Epson WS-Config SOAP | Dispatch table at `0x5baf0c` has `GetData`, `SetData`, `GetFile`, and `SetFile` actions under `http://schemas.epson.net/ws/2008/07/config/`. The `SetData` handler at `0x2029c0` parses a request and forwards a command through the printer-controller interface at `0x116994`. | Web Config reports WSD enabled. Unauthenticated GETs of `/Epson_WS_Config` and `/WSD/DEVICE` returned 404 over HTTP and HTTPS. One standards-based WS-Discovery multicast Probe received no response from the printer on this network. SOAP POST availability was not tested. | `SetData` is a genuine configuration action in the extracted program, but accepted keys, authorization, and live reachability are unresolved. No arbitrary Linux file write is established. |
| WS-Config file actions | The `GetFile` handler at `0x202158` and `SetFile` handler at `0x20229c` have nearly identical control flow. After state checks, each emits a SOAP response/fault through `0x1e7348`; neither parses a file path or body or calls a file-writing routine. | No file action sent. | The action names do not provide an identified route to `/opt/nwsoc_data/ExtBoot`. |
| ENPC | UDP 3289 packet parser and authenticated configuration session documented in [ENPC/DHCP lead](enpc-dhcp-lead.md). | Read-only discovery and same-value write accepted after administrator authentication; shell-character probes did not establish storage. | Network setting write, with no code execution or file write demonstrated. |
| Firmware updater | `EPFWUPD.exe` includes `/firmwareupdate/checknew`, `/firmwareupdate/writenew`, `/FIRMWAREUPDATE`, `/FIRMWAREUPDATE/ADMINCHECK`, `/DOWN/FIRMWAREUPDATE/{MAIN,NET,ROM1,ROM2}`, `/update.cgi`, and `/cgi_page_down`. It imports `BCryptVerifySignature`. | Prior HEADs of lowercase routes returned 404. One HTTP GET of uppercase `/FIRMWAREUPDATE` returned 200; subsequent GETs returned 500. No upload was attempted. | Generic updater paths and host-side signature verification exist. Applicable transport and device-side checks for this model remain unverified. |
| Epson cloud | `nwsoc` contains production and staging `DSSWebService/SOAPRelayProxy.aspx` URLs. | No cloud service contacted for this research. | These are outbound service addresses, not local administrator routes. |

The recovery download is [labeled USB-only by Epson](https://epson.com/Support/Printers/All-In-Ones/ET-Series/Epson-ET-3850/s/SPT_C11CJ61201). Epson's [security overview](https://support.epson.net/security/en/index.html) describes device-side firmware signature checking for some product families; the ET-3850's exact enforcement has not been established. The current network research has **not** produced a safe custom-firmware installation path.

## Next static question

For `WS-Config SetData`, determine the accepted key namespace and the controller-side authorization before any live write. It is a settings interface; the extracted handler does not show an arbitrary Linux file path parameter. Separately, trace the Windows updater's model selection and signed-image checks before treating its generic URL list as ET-3850 network-flash support.
