# ENPC hostname to DHCP shell: static research lead

The XB22Q5 `nwsoc` binary contains a potential command injection chain. This is **not a confirmed vulnerability** or an installation method. A read-only `N` request received a 14-byte `EPSONn` reply from UDP 3289. A same-value configuration write has also been accepted through a short-lived session authenticated with the existing Web Config administrator credential; readback showed the network fields were unchanged.

## Observed code path

1. `nwsoc` binds a UDP socket to network byte order `0x0cd9` (port 3289). Its parser expects the five-byte `EPSON` prefix. The packet dispatcher at `0x1babd0` routes `I` command `0x18` to `0x1bf8b0`, and the `S` command family has a similar writer at `0x1be950`.
2. The writers use `0x1c6cc8` to measure a bounded string. That helper counts bytes up to a NUL or limit; it does not itself restrict shell metacharacters. The writers pass packet bytes to the generic configuration setter for `IP_HOST_NAME` and `IP_DOMAIN_NAME`. Other validation can occur downstream. They check length and packet/interface conditions, including a matching device MAC. The dispatcher consults `PS_PCD_SECURITY_FLAG`. Live testing showed `I/0x18` reaches its handler, then returns `0x20` outside a configuration session. A session opened with the existing administrator credential, accepted a same-value write with status `0x00`, and closed with status `0x00`. A zero-length password proof returned `0x10`; no authentication bypass was demonstrated.
3. Separately, `0x1a0908` calls `0x19dbbc`, which reads `IP_HOST_NAME` from the `IP` scope, into the buffer used in its `./startup_dhcp.sh %s %d %s %s %s %s %s%s` command string. This is the **same scope and key** as the ENPC writer. The `IP_CURRENT` fields read elsewhere in `0x19ef70` are addresses and activation state, not the hostname source for this command. The local configuration routine at `0x19ef70` validates hostname characters before writing them. The ENPC writer's own branch shows length checks rather than that character validation.

## Missing link

The `IP` to `IP_CURRENT` transition is no longer a missing link for the DHCP command's hostname argument: direct constant tracing shows `0x19dbbc` reads `IP`/`IP_HOST_NAME`. On this live printer, an authenticated write of a harmless shell expression to the hostname field returned status `0x00` but did **not** change the field: `PS_COMMON_DEVICE_NAME_INDIVIDUALLY_SET` was clear, so the handler ignored the supplied hostname. An analogous domain-field expression returned status `0x10` and did not change the field. In both tests the original network fields were re-sent and verified unchanged before the session closed. The eleven direct references to that mode key in the analyzed `nwsoc` image are reads, including one instruction at `0x6FCE8` not yet assigned to a function. No setter for the bit has been identified. This ENPC route has not established shell-character storage or command execution.

## Safe next verification

The browser-side Web Config Basic page rejects shell characters in Device Name. Direct submission of a harmless shell expression to `NW_BASIC/CONFIRM` reflected it. Submitting that confirmation to `NW_BASIC/SET` returned HTTP 200 with no explicit error, but the immediately fetched Basic page still had the original Device Name. A later, separate read also showed the original name. To distinguish input rejection from an unapplied settings page, a second reversible test submitted a legal temporary name (`ET3850TEST`) through the same confirmation and SET flow. It too returned HTTP 200 without an error, and immediate readback still showed the original name. The original name was re-submitted and verified visible afterward. No printer restart was performed. Thus the immediate readback cannot establish that either value was stored, and the shell expression is not an injection proof. The ENPC `I` and `S` writers both test a mode bit before copying packet hostname bytes; that bit was clear in the live configuration. Trace how that mode bit can be set and whether a changed `IP_HOST_NAME` reaches the DHCP launcher before interpreting this as a command-execution path. Only a reproducible, reversible impact should be promoted to a disclosure report.
