# ET-3850 LCD background assets

**Correction from the owner:** the active home screen is white with blue tiles. The blue-wave PNG below is a stock resource, but its role as the active home-screen background has not been established. The solid white 320x240 PNG is at decoded offset `0xb14564` and is only 104 bytes; whether the home screen draws directly from it or uses it as one color choice needs a display/resource trace.

The decoded controller image from RCX `CROM` record `0x16da122` contains a 320×240 PNG at decoded offset `0xb0e93c`. It is the blue wave background identified by the owner. The image is 22,014 bytes, with a 256-entry `PLTE` chunk and three `IDAT` chunks. The same resource group contains solid black, blue, and white 320×240 PNGs, menu bars, icons, and 320×240 WebP help illustrations. Strings in the decoded image include `HOME_BGCOLOR_SETTING`, `BG_COLOR_SETTING`, and `SCREENSAVER_SETTING`. Epson's [ET-3850 Basic Settings guide](https://download4.epson.biz/sec_pubs/et-3850_series/useg/en/GUID-F463AE8C-C46F-40CB-90CA-8FC8AEFD1052.htm) confirms that `Settings > General Settings > Basic Settings > Wall Paper` changes the home screen's background color.

The owner requested a late-1990s keygen/demoscene look. [A violet and cyan concept preview](../assets/demoscene-wave-preview.png) and [its 320×240 version](../assets/demoscene-wave-320x240.png) are saved in this repository. A 32-color conversion is [18,381 bytes](../assets/demoscene-wave-320x240-32color.png), below the stock PNG's byte count. That byte count does **not** make it a drop-in image: the containing CROM stream uses Huffman-coded copy/literal items, and an arbitrary PNG replacement would change bytes referenced by other items unless the CROM is re-encoded or the mapping is handled carefully.

A narrower color edit is proven offline. The CROM decoder's provenance map showed 21,467 of the stock PNG's 22,014 decoded bytes came directly from literal bytes; the remainder came from copy items. Its palette and palette CRC can be changed by editing selected unique literal bytes while leaving literals shared with other UI content untouched. A violet/cyan transform changed 707 palette literal sources plus the four CRC bytes in the compressed CROM. Re-decoding the modified CROM produced the same 16,640,728-byte output length and changed **742 decoded bytes, all inside this PNG**. The [extracted recolored PNG](../assets/palette-patched-wave-320x240.png) passes PNG CRC and Pillow decoding. Its SHA-256 is `642eeba97fe1746ce00ef1e02c9ff515caf31f00f120eb27a2290a6fb9cf8aa0`.

This proves a limited custom color background can be built in an offline controller image without disturbing other decoded resources. It does not show that the printer accepts a modified RCX, that this CROM record can be flashed by our transport, or that a custom photo/full-picture replacement will fit the existing compressed stream. The custom UI and Wi-Fi changes remain offline candidates.
